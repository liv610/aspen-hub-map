Data used in this prototype

  • States: U.S. Census cartographic boundaries via us-atlas 3.0.1 (Albers USA, Alaska and Hawaii inset).
  • Appalachia: merged Census county shapes for the Appalachian Regional Commission counties (Wikipedia's ARC list, 420 counties, plus 8 Virginia independent cities). ARC currently lists 423, so reconcile with arc.gov before launch.
  • Tribal lands: Census TIGERweb AIANNH (current): 312 federal reservations, 177 off-reservation trust lands, 10 state reservations and 74 Hawaiian Home Lands as legal areas. 287 statistical areas (Oklahoma, Alaska Native village, state- and tribal-designated) are drawn differently.

Hub data, provisional

  • 119 Hubs and their states come from the live aspencsg.org map. MDC's 13 states are verified from that map: AL, AR, FL, GA, KY, LA, MS, NC, SC, TN, TX, VA, WV.
  • Indigenous-serving: 9 Hubs, the 7 the current map labels with a nation plus Oweesta Corporation and NACDC Financial Services, which the map notes as national Native intermediaries. The Hubs sheet has 17 and should replace this list.
  • Appalachia membership (11 Hubs) is inferred: Hubs serving West Virginia plus Hubs named for Appalachia. Funders, other regions and most descriptions are pending the Hubs sheet.

Scenario

Evaluation

Recommendation: Treatment D

D separates the questions the brief asks by using a different form for each layer, so the map still reads without color:

  • "Where am I exploring?" is one continuous boundary line, blue with a dark casing so it stays visible over any fill. Nothing else on the map is drawn as a thick line.
  • "Where does this Hub work?" is a filled, hatched area with one merged outer edge. Thirteen MDC states read as one footprint, not thirteen separate shapes competing with the region.
  • "How do they relate?" is answered by drawing order and focus. The region line always sits above the footprint, and everything outside region ∪ footprint is dimmed one step, so the overlap and the parts beyond the region are both obvious.
  • Tribal lands are small solid warm shapes, a third form that is neither line nor hatch. Statistical areas are dashed so they never read as legal boundaries.

A is the most familiar, but the fills bury the region and depend on color. B is the lightest, but two outline systems fight along state lines and the footprint has no "inside". C fixes color dependence but stays busy because every state border is redrawn. D keeps C's pattern and removes that noise.

Recommended visualization system (Treatment D)

Map styling expressed as tokens and rules so it can go straight into Figma components and the SVG implementation.

Layer styles

Layer order (bottom → top)

  1. Base states: one muted slate-blue, no distinction between states with and without Hubs
  2. Selected Hub footprint: sage fill + diagonal hatch
  3. Tribal lands (only when Indigenous-serving is on)
  4. Interior state borders (fade to 35% when tribal lands are on)
  5. Focus dim: everything outside region ∪ footprint, one step darker
  6. Footprint merged outer edge
  7. Selected state or region: dark casing, then blue line, with a 16% blue tint inside
  8. Hover outline
  9. State labels and callouts

Legend behavior

  • Default: no legend. The map is one tone, and the tooltip carries the Hub count.
  • State or region selected: one item, the selected boundary.
  • Hub selected: adds the footprint item and the disclaimer "Highlighted states show where Hubs work, not necessarily statewide coverage."
  • Indigenous-serving on: adds tribal lands (legal areas and statistical areas as separate items) and the note that they are reference geography, not Hub service areas.
  • Each swatch is drawn with the same SVG treatment as the map, and items appear in layer order.

Non-color cues

  • Region or state: thick cased line. It's the only thick line on the map.
  • Hub footprint: 45° hatch + thin light edge.
  • Tribal legal areas: solid fill with light edge, and small areas get a minimum-size diamond.
  • Tribal statistical areas: dashed edge, no fill.
  • Hover: white outline + tooltip. Selection is never shown by color alone.
  • Map label: the map's text label always names the active layers, for screen readers.

Details worth keeping

  • Small states: VT, NH, MA, RI, CT, NJ, DE, MD and DC get callout labels with leader lines. Hover and selection still work on the shape itself, and keyboard users reach them by arrow key.
  • Small tribal areas: areas below about 1 px on screen get a 2.4 px diamond marker so they don't disappear. They keep the official Census name in the tooltip.
  • Large footprints: the hatch is low-contrast and the edge is merged, so a 13-state Hub reads as one calm shape. Focus dimming keeps the rest of the country from competing.
  • Alaska and Hawaii insets: they follow the same rules. Region boundaries never cross into the insets.
  • Narrow screens: the map spans full width and the panel stacks below it. Under 600 px, the agreed mobile list view takes over.

Interaction specification

What changes on the map, in the panel and in the legend for each action. The Prototype view implements all of these.

Rules that resolve the tricky cases

  • One browsing context at a time (a state or a region), plus at most one selected Hub. Selecting a Hub never replaces the context, and deselecting returns to it exactly.
  • A map click always means "browse this state". It switches to the States tab, clears the region and closes any open Hub. Clicking the selected state again clears it.
  • Indigenous-serving filters the list and adds the tribal reference layer. It never changes the browsing context. If the context has no matching Hubs, the panel says so and offers to show them nationwide while keeping the context drawn.
  • Tribal areas are not clickable. They have hover and focus tooltips with the official Census name and area type, because they are reference geography, not a way to browse Hubs.
  • Hubs with no assigned region are still found through the States and Hubs tabs, search and the Indigenous-serving filter. The card says "No region assigned" and never infers one.

Technical implementation notes

Recommended approach for the WordPress build, and where we still need answers.

Recommended approach: custom SVG from TopoJSON, no map framework

This prototype is that approach. It uses topojson-client (about 10 KB) to decode one pre-projected topology and ordinary SVG for every layer. There's no tile server, API key or mapping framework, and it works as a single enqueued script inside the existing WordPress page.

  • Build step (Node, run when boundaries change): us-atlas or the Census cartographic boundary file, then mapshaper or topojson to simplify. Regions are made by merging county FIPS lists, and TIGER AIANNH layers are clipped and simplified. The output is one ~200 KB topology.
  • Runtime: footprints are merged on the fly with topojson.merge, so any Hub's states make one outline. The region outline shares arcs with the state borders, so boundaries line up exactly.
  • Data: Google Sheet → WordPress Hub post type → JSON endpoint (Hubs, state codes, region slugs, funders, Indigenous-serving flag). Geography stays in the static topology.
  • Accessibility: the map is one tab stop with roving focus (arrow keys move between states, Enter selects). Every map action has a toolbar equivalent, and live regions announce changes.
  • Use MapLibre only if the client later wants zooming to reservation or county detail. It's not needed for the current scope.

Can implement confidently

  • State selection, hover, roving keyboard focus and tooltips
  • Appalachia from ARC county list, merged in the build step
  • Footprint merge, hatch patterns, casing, focus dim (SVG mask)
  • Contextual legend generated from the same tokens
  • Tribal reference layer from TIGER AIANNH, refreshed yearly
  • Responsive layout and mobile list fallback

Needs technical investigation

  • Total payload on slow connections: test the ~200 KB topology plus the WordPress page. Consider lazy-loading the tribal layer.
  • Very small reservations and rancherias: marker sizing and hover targets on touch screens
  • Rendering performance of the 860 tribal shapes plus the mask on older mobile devices
  • GA4 events for map interactions versus list interactions

Needs client clarification

  • County lists for the other nine regions, especially Black Belt, Southwest and Plains, which have no official definition
  • Appalachia: confirm the ARC definition and the current 423-county list
  • Which tribal area types to show. Statistical areas include Oklahoma (where Census still uses OTSAs) and Alaska Native villages. Also confirm wording and whether names appear on hover
  • The 17 Indigenous-serving Hubs and any nation associations to show on cards
  • Whether a map click in Regions view should switch to States (as specified) or stay in the region
